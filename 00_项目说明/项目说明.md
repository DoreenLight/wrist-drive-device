# 腕部驱动设备项目说明

> 本说明由代码目录静态阅读整理，未连接真实硬件验证。当前目录中主要是一个基于 Qt 6 / C++ 的串口上位机项目，用来调试、控制和记录“腕部驱动/康复设备”的电机、传感器和康复流程数据。
>
> 补充（2026-10-16）：本文档的源码结论已经逐行核对；另外当天对现场设备做了**只读实测**（串口枚举、UI 控件树、error_frames.txt 全量解析），结果记录在 `需求_轨迹跟踪视图改造.md` 第 1、6 节。

## 1. 这个文件夹是干什么的？

这是一个“腕部驱动设备”的 PC 端控制与调试软件工程。它的核心用途是：

1. 通过串口连接下位机/MCU/电机控制板；
2. 按自定义二进制协议发送控制命令；
3. 接收 MCU 上传的电机、IMU、六维力传感器等遥测数据；
4. 在界面中显示曲线、状态、日志和诊断信息；
5. 对腕部康复相关流程进行启停、参数下发、数据记录。

从代码看，它不是普通文档或单片机固件，而是一个 Windows 桌面上位机程序，工程名为 `Uart_controller`。

## 5. 串口通信协议

协议定义集中在 `floatiddefs.h` 和 `protocolworker.cpp`。

### 5.1 帧格式

一帧数据格式为：

```text
SYNC_H  SYNC_L  LEN  CMD  PAYLOAD...  SUM  END
0x6C    0x67    1B   1B   LEN字节     1B   0xED
```

字段含义：

| 字段 | 含义 |
|---|---|
| `SYNC_H` | 帧头高字节，固定 `0x6C` |
| `SYNC_L` | 帧头低字节，固定 `0x67` |
| `LEN` | 载荷长度，最大 `250` |
| `CMD` | 命令码 |
| `PAYLOAD` | 命令载荷 |
| `SUM` | 校验和 |
| `END` | 帧尾，固定 `0xED` |

校验和计算方式：

```text
SUM = (LEN + CMD + payload所有字节求和) & 0xFF
```

### 5.2 上位机发给 MCU 的命令

| 命令码 | 名称 | 作用 |
|---|---|---|
| `0x01` | `IO_WRITE` | 写 IO/控制量，例如启停、模式切换 |
| `0x02` | `FLOAT_WRITE` | 写入单个浮点参数 |
| `0x03` | `BATCH_WRITE` | 批量写入多个浮点参数 |
| `0x84` | `PING` | 通信测试 |
| `0x85` | `FLASH_SAVE` | 请求下位机保存参数到 Flash |

### 5.3 MCU 发给上位机的命令

| 命令码 | 名称 | 作用 |
|---|---|---|
| `0x81` | `TELEMETRY` | 上传遥测数据 |
| `0x82` | `IO_REPORT` | 上报 IO 状态 |
| `0x83` | `ACK` | 命令应答 |

### 5.4 载荷格式

#### `IO_WRITE`

```text
[io_id:1B] [value:1B]
```

#### `FLOAT_WRITE`

```text
[float_id:1B] [float_value:4B little-endian IEEE754]
```

#### `BATCH_WRITE`

```text
[count:1B] ([float_id:1B] [float_value:4B little-endian IEEE754]) * count
```

#### `TELEMETRY`

```text
[count:1B] ([float_id:1B] [float_value:4B little-endian IEEE754]) * count
```

#### `ACK`

```text
[ack_cmd:1B]
```

#### `IO_REPORT`

```text
[io_id:1B] [value:1B]
```

### 5.5 错误帧记录

协议解析器会检查帧头、长度、帧尾和校验和。如果发现校验失败，会把错误帧记录到程序运行目录下的：

```text
error_frames.txt
```

当前构建目录中已经存在该文件，说明曾经出现过通信错误或调试数据。

## 9. 使用时的注意事项

1. 该软件会向设备下发电机启停、模式切换、康复动作等命令，连接真实硬件时应确保设备处于安全状态。
2. 下发 `FLASH_SAVE` 可能会让下位机保存参数到 Flash，属于持久化操作，使用前应确认参数正确。
3. `M2 机械零点`、`M2 清除故障`、力传感器清零等操作会影响设备状态，建议在明确硬件状态后使用。
4. CSV 数据和错误帧日志默认写在程序运行目录，不一定写在源码目录。
5. `build/` 是构建产物目录，重新构建时可能被覆盖。
6. 当前 Git 状态中源码和构建产物已有修改，若要继续开发，建议先整理 `.gitignore`，避免把构建产物、日志和 CSV 数据长期纳入版本控制。
