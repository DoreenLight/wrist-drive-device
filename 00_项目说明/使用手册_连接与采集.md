# 使用手册 — 连接设备与采集数据

本文说明**如何把上位机连上腕部驱动设备，并把遥测数据采集为 CSV 文件**。

> 本文所有界面名称、按钮名称均与实际程序一致（依据 `01_上位机程序/mainwindow.cpp` 源码）。
> 名词看不懂时看 `设备与数据说明/术语与名词.md`；参数 ID 含义看 `设备与数据说明/数据字典.md`。

---

## 1. 前置条件

| 项目 | 要求 |
|---|---|
| 腕部驱动设备 | 已通电（USB 只供通信，**执行器通常需要单独供电**） |
| USB 线 | 连接电脑与设备 |
| 串口驱动 | **CH343SER**（本设备为 CH342 芯片）。未装则不会出现 COM 口 |
| 上位机程序 | `build/Desktop_Qt_6_8_2_MinGW_64_bit_Release/Uart_controller.exe` |

驱动确认方法：打开**设备管理器 → 端口（COM 和 LPT）**，应能看到**两个**端口：

```text
USB-Enhanced-SERIAL-A CH342 (COM12)   ← A 路
USB-Enhanced-SERIAL-B CH342 (COM13)   ← B 路，本设备的协议口
```

> **为什么是两个口？** CH342 是 USB 转**双串口**芯片，插一次会出现两个 COM 口，属正常现象。
> 哪一路接了 MCU 协议串口由硬件接线决定。详见 `设备与数据说明/术语与名词.md` 第 2.7 节。
>
> 端口号（COM12/COM13）由 Windows 分配，换机器会变；**判断依据是名字里的 `-A` / `-B`**。

## 2. 界面总览

程序首页有 **4 个入口按钮**：

| 首页按钮 | 页面用途 |
|---|---|
| **串口配置与调试** | 通用串口助手：HEX 收发、定时发送。用于排查原始字节 |
| **协议调试** | 按协议收发指令、查看遥测表与帧统计。**连接设备主要用这一页** |
| **电机控制调试** | 系统启停、M1/M2 模式与参数、实时曲线、六维力 |
| **康复治疗** | 被动/主动康复参数与启停、康复曲线、力传感器、**数据记录** |

每个页面左上角都有 **`返回首页`** 按钮。

## 3. 打开串口（在「协议调试」页）

1. 首页点击 **`协议调试`**；
2. 左侧 **`串口配置`** 组 → 点击 **`刷新`** 按钮（程序启动时也会自动刷新一次）；
3. **`端口`** 下拉框选择 **B 路**那一个（名称带 `-B CH342`，本机为 COM13）；
   ⚠️ **不要选 A 路**，A 路无应答；
4. **`波特率`** 下拉框选择 **230400**（本页默认值就是 230400）；
5. 点击 **`打开串口`** 按钮。

本设备**实测确认**的通信参数：

| 参数 | 值 |
|---|---|
| 端口 | B 路（`-B CH342`，本机 COM13） |
| 波特率 | **230400** |
| 数据位 | 8 |
| 校验位 | 无 |
| 停止位 | 1 |
| 流控 | 无 |

打开成功的标志：

- `打开串口` 按钮变成 **`关闭串口`**；
- 底部状态栏由「请先打开串口。」变为连接信息；
- 左侧 **`帧统计`** 组开始有数字变化。

> 如果点了 `打开串口` 但没有反应，先确认**没有其他程序占着这个端口**
> （例如另一个串口助手、或已打开的另一个上位机实例）。

## 4. 如何发送 PING

**PING 是纯通信测试命令，不会引起任何电机动作，可以放心点。**

### 操作步骤

1. 先完成第 3 节，把串口**打开**（否则点 PING 只会提示「请先打开串口。」）；
2. 在「协议调试」页左侧找到 **`快速命令`** 组；
3. 点击其中的 **`Ping 心跳`** 按钮（同组另外两个是 `启动电机` / `停止电机`，**先不要点**）。

```text
协议调试页 · 左侧
┌─ 串口配置 ────────────────┐
│ 端口 [COM13 ▾]      [刷新] │
│ 波特率 [230400 ▾] [打开串口]│
└───────────────────────────┘
┌─ 快速命令 ────────────────┐
│ [Ping 心跳] [启动电机] [停止电机] │  ← 点最左边这个
└───────────────────────────┘
```

### 点击后应该看到什么

| 观察位置 | 正常表现 |
|---|---|
| **`诊断日志`** 组 | 出现 `→ 发送 PING` |
| **`帧统计`** → `ACK帧` | 计数**增加**（设备回复了 ACK） |
| **`帧统计`** → `校验错` | **保持 0 或不增长** |
| 底部状态栏 | 显示连接/统计信息 |

### PING 到底是什么

点击后程序发出的 6 个字节：

```text
6C 67 00 84 84 ED
```

设备正常时会回：

```text
6C 67 01 83 84 08 ED
│  │  │  │  │  │  └─ END = 0xED
│  │  │  │  │  └──── SUM = 0x08（校验正确）
│  │  │  │  └─────── 应答命令 = 0x84（即 PING）
│  │  │  └────────── CMD = 0x83（ACK 应答）
│  │  └───────────── LEN = 1
│  └──────────────── SYNC_L
└─────────────────── SYNC_H
```

帧格式与命令码全表见 `串口协议说明.md`。

### 点 PING 没反应 / ACK 不增加

按顺序排查：

1. **串口没打开** —— 底部状态栏是否提示「请先打开串口。」；
2. **选错端口** —— 换成另一个 `CH342` 端口（A/B 交换）再试；
3. **波特率不是 230400** —— 本设备只有 230400 有应答，其他速率设备**完全不应答**；
4. **设备未供电** —— USB 只供通信，MCU 需要设备自身电源；
5. **`打开串口` 没真正成功** —— 按钮文字是否已变成「关闭串口」；
6. **端口被占用** —— 关掉其他串口工具后重开。

> 若 `ACK帧` 在增加但 `校验错` 也快速增加，说明**能通信但链路质量差**，
> 这是设备侧发送的问题，不是操作问题。详见 `串口连接排查记录.md`。

## 5. 采集数据的完整流程

下面是**从零到拿到 CSV 文件的完整步骤**，界面名称与程序实际一致。

### 步骤 1 — 连接并打开串口

按第 3 节操作（协议调试页 → COM13 → 230400 → 打开串口）。

### 步骤 2 — 用 PING 确认通信

按第 4 节点一次 **`Ping 心跳`**，确认 `ACK帧` 有增长。

### 步骤 3 — 让设备开始上传遥测

**这一步很关键**：只有设备在上传遥测帧，记录才有内容。

进入 **`电机控制调试`** 页（首页 → `电机控制调试`）：

1. 点右上角的 **`系统启动`** 按钮 ——
   这会向设备发送 IO `0x0A = 1`，启动 MCU 的 **TIM2 控制循环**。
   ⚠️ **不启动系统，电机不会动作，也可能不上传遥测**；
2. 观察页面变化：
   - `Motor1 数据` / `Motor2 数据` 的五格数值开始刷新（不再是 `—`）；
   - `六维力传感器 (DR304)` 的 Fx~Mz 开始显示数值；
   - 实时遥测曲线可以勾选要看的量：
     曲线下方的复选框（如 `M1 轨迹输入`、`M2 规划位置`）勾上即显示对应曲线。

> ⚠️ **安全提醒**：点 `系统启动` 后，若设备已使能电机，电机可能立即响应既有指令。
> 首次调试请确保设备处于**空载**状态，并且急停/断电手段可用。

### 步骤 4 — 进入「康复治疗」页并开始记录

1. 点 **`返回首页`** → 点 **`康复治疗`**；
2. 在页面**下方**找到 **`治疗日志`** 组；
3. 点击组内的 **`● 开始记录`** 按钮。

按钮会变成 **`■ 停止记录`**（绿色变红色），底部状态栏提示
`正在记录数据 → 20261015_201530`，日志里出现 `开始记录数据 → ...`。

> **此时数据只在内存里，还没有写文件**——见步骤 6 的说明。
>
> 记录与**当前停留在哪个页面无关**：开始记录后可以自由切到电机页、协议页做操作，
> 数据照常被记录。

### 步骤 5 — 执行你要采集的过程

在记录期间按需操作，例如：

- **被动康复**：康复页 → `Motor1 康复` / `Motor2 康复` 面板 →
  「被动」选项卡 → 设置 `最小(°)` `最大(°)` `循环:` → 点 `▶ 启动`；
- **主动康复**：切到「主动」选项卡 → 填 `T波速度` `极限角1/2` `停顿时间`
  `Tmax`/`Fmax` `刚度k` → 点 `▶ 启动`；
  M2 还需先在「模式」里选 `掌屈/背屈 (Fy)` 或 `尺偏/桡偏 (Fz)`；
- **手动控制电机**：到 `电机控制调试` 页操作 M1/M2；
- **下发参数**：到 `协议调试` 页用 `Float 写入` 或 `批量写入`。

参数含义与单位见 `设备与数据说明/数据字典.md`。

### 步骤 6 — 停止记录（**最容易漏掉的一步**）

回到 **`康复治疗`** 页 → `治疗日志` 组 → 点击 **`■ 停止记录`**。

**只有点这一步，数据才会真正写入 CSV 文件。**

停止后：

- 按钮变回 `● 开始记录`；
- 状态栏显示 `数据记录已停止 (共 N 帧, M 列)`；
- 日志里出现 `数据记录已停止: N 帧, M 列`。

> ⚠️ **记录过程中直接关闭程序，内存里的数据会全部丢失。**
> 一定要先点 `■ 停止记录`。

### 步骤 7 — 找到 CSV 文件

文件写在 **exe 所在目录**（不是 `02_采集数据/`）：

```text
build\Desktop_Qt_6_8_2_MinGW_64_bit_Release\telemetry_YYYYMMDD_HHmmss.csv
```

文件名里的时间取**开始记录**的时刻。

### 步骤 8 — 归档到采集数据目录

把 CSV **复制**到：

```text
02_采集数据\telemetry\
```

该目录已被 `.gitignore` 排除，不会被上传到 GitHub。

## 6. CSV 文件内容

| 项目 | 说明 |
|---|---|
| 第一列 | `时间`，格式 `hh:mm:ss.zzz`（毫秒精度） |
| 其余列 | **只包含本次记录中实际上传过的参数 ID**，按首次出现顺序 |
| 列名 | 取参数名称（如 `M1 轨迹输入`）；未定义的 ID 写作 `0x??` |
| 数值 | 定点 3 位小数；某帧没有该参数时**留空**（不会填 0） |
| 编码 | UTF-8，LF 换行 |

示例：

```csv
时间,M1 轨迹输入,M1 反馈角度,M2 规划位置,Fx,Fy,Fz
09:12:31.004,0.000,0.512,12.300,0.120,-1.450,0.030
09:12:31.024,0.000,0.518,12.310,0.118,-1.448,0.031
```

列名与参数 ID 的完整对照见 `设备与数据说明/数据字典.md` 第 3、6 节。

> **精确分析请用 CSV，不要用界面曲线。**
> 曲线由 50 ms 定时器批量刷新，多帧合并时同 ID 只取最后一帧，
> 属于降采样后的趋势图，不是原始逐帧数据。

## 7. 界面已知行为（不是故障）

| 现象 | 原因 |
|---|---|
| 康复页「实时状态」的 **`运行: 00:00:00` 永远不走** | 源码中计时器 `treatTimer` 创建后未启动，`treatRunning` 也从未置为 `true`。不影响康复与记录 |
| 康复页没有「暂停」按钮 | 实际面板只有 `▶ 启动` / `■ 停止` 两个按钮（头文件里残留的暂停控件未使用） |
| 曲线纵轴超出范围时画到框外 | 纵轴固定 `-5 ~ +5` |
| 协议页 `启动电机 / 停止电机` 操作的是 M1 | 它们固定发送 IO `0x01`（M1 启停）。**系统启停**只在电机页的 `系统启动` / `系统停止` |
| 遥测表格里只出现部分参数 | 表格只显示字典里定义过的 ID |

## 8. 常见问题

### 8.1 设备管理器里看不到 COM 口

驱动未安装或线缆/接口问题。本设备需要 **CH343SER**（不是 CH341SER）。
安装与排查过程见 `串口连接排查记录.md`。

### 8.2 能打开串口，但 PING 没有 ACK

见第 4 节末尾的排查顺序（首要怀疑：选错 A/B 路、波特率不是 230400、设备未上电）。

### 8.3 状态栏/日志一直提示「请先打开串口。」

`打开串口` 没有成功。检查按钮文字是否变成「关闭串口」、端口是否被别的程序占用。

### 8.4 记录完成后 CSV 是空的或没有文件

| 可能原因 | 处理 |
|---|---|
| 忘记点 `■ 停止记录` | 数据还在内存中，回到程序点一次即可 |
| 记录期间设备没上传遥测 | 确认已点 `系统启动`，且 `帧统计` 的 `遥测帧` 在增长 |
| 链路误码严重 | 看 `校验错` 是否快速增长，若是则属设备侧发送问题 |
| 找错目录 | CSV 在 **exe 所在目录**，不是 `02_采集数据/` |

### 8.5 `校验错` 数持续快速增长

说明能通信但链路质量差。本设备实测存在此现象，
原因分析与后续排查方向见 `串口连接排查记录.md` 第 6～8 节。

## 9. 安全提示

1. **首次测试不要直接佩戴到人体上**，先空载验证方向、限位、速度是否正常；
2. 确认急停开关或断电方式随时可用；
3. 第一次运行时把角度和速度范围设小一些；
4. 以下操作会改变设备状态或持久化参数，使用前务必确认：

| 操作 | 位置 | 风险 |
|---|---|---|
| `系统启动` | 电机页 | 电机可能立即响应既有指令而动作 |
| `设机械零点` | 电机页 M2 面板 | 改变零点基准，影响此后所有位置控制 |
| `清除故障` | 电机页 M2 面板 | 可能掩盖真实故障 |
| `归零` | 康复页 六维力传感器 | 改变力/力矩零点基准，影响主动康复力闭环 |
| `存入 Flash` | 电机页右上角 | 参数写入 MCU 非易失存储，掉电仍生效 |
| 主动康复 `▶ 启动` | 康复页 | 力控模式，可能产生非预期运动 |
