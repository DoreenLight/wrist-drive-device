# 使用手册 — 连接设备与采集数据

本手册说明如何把上位机连接到腕部驱动设备，并把遥测数据采集为 CSV 文件。

---

## 1. 准备清单

| 项目 | 说明 |
|---|---|
| 腕部驱动设备本体 | 含电机控制板 / MCU |
| 设备电源 | 先供电，确认设备处于安全状态 |
| USB 转串口线 | 或设备自带 USB 串口 |
| 串口驱动 | CH340 / CP210x / FTDI 等，取决于硬件 |
| 上位机程序 | `build\Desktop_Qt_6_8_2_MinGW_64_bit_Release\Uart_controller.exe` |

---

## 2. 连接硬件

1. 给腕部驱动设备供电；
2. 用 USB / 串口线连接电脑与设备控制板；
3. 打开 **设备管理器 → 端口（COM 和 LPT）**；
4. 找到并记住串口号，例如：

```text
USB-SERIAL CH340 (COM3)
Silicon Labs CP210x (COM5)
USB-Enhanced-SERIAL-A CH342 (COM12)   ← 本设备（A 路）
USB-Enhanced-SERIAL-B CH342 (COM13)   ← 本设备（B 路，协议口）
```

> **本设备是 CH342 双串口芯片，插上后会同时出现两个 COM 口**，这是正常现象，
> 原因见 `串口连接排查记录.md` 第 2 节。

> 如果在设备管理器里看不到任何 COM 口，说明驱动未安装或线缆接触不良，
> 需要先解决驱动问题，上位机不会列出该端口。

---

## 3. 启动上位机

双击：

```text
build\Desktop_Qt_6_8_2_MinGW_64_bit_Release\Uart_controller.exe
```

窗口标题为 **“腕关节康复设备串口控制台”**。

程序包含 5 个页面：

| 页面 | 用途 |
|---|---|
| 首页 | 功能入口 |
| 串口调试 | 通用串口助手：收发原始数据、HEX 显示、定时发送 |
| 协议调试 | 按协议收发命令、看遥测表格与协议日志 |
| 电机控制调试 | M1 / M2 启停、模式、参数、曲线图 |
| 康复治疗 | 康复参数设置、开始/暂停/停止、数据记录 |

---

## 4. 打开串口（推荐用“协议调试”页）

1. 进入 **协议调试** 页；
2. 点击 **刷新串口**；
3. 从下拉框选择设备管理器里看到的 COM 口；
4. 选择 **波特率**（必须与下位机固件一致）；
5. 点击 **打开串口**。

> **本设备已实测确认的参数**（详见 `串口连接排查记录.md`）：
>
> | 参数 | 值 |
> |---|---|
> | 端口 | **COM13**（CH342 的 B 路；A 路 COM12 无协议应答） |
> | 波特率 | **230400** |
> | 帧格式 | 8 数据位 / 无校验 / 1 停止位 / 无流控 |
>
> ⚠️ 端口号由 Windows 分配、会随插入环境变化，请以设备管理器实际显示为准；
> 但**要选 B 路**（名称里带 `-B CH342`）那一个。

打开成功后：

- 状态栏显示串口已打开；
- 协议日志开始出现内容；
- 顶部统计标签（总帧数 / 校验错误）开始变化。

---

## 5. 验证通信

### 5.1 发送 PING

点击 **PING** 按钮。正常情况下下位机返回 `ACK`，日志中出现应答记录。

### 5.2 看统计标签

| 指标 | 正常表现 |
|---|---|
| 总帧数 | 持续增长 |
| 校验错误数 | 不增长，或极低速增长 |

### 5.3 收不到数据的排查顺序

1. **COM 口选错** — 刷新后重新确认；
2. **波特率不匹配** — 本设备固件为 **230400**；用其它速率会**完全收不到数据**（设备把无效帧直接丢弃）；
3. **设备未供电** — 检查电源指示灯；
4. **TX/RX 接反** — 交换两根数据线；
5. **未共地** — 确认 GND 相连；
6. **下位机固件未运行** — 确认 MCU 已烧录并启动；
7. **下位机不主动上传遥测** — 可能需要先点“系统启停”启动控制循环；
8. **端口被其他软件占用** — 关闭其他串口助手后重开。

> 校验错误持续快速增长，基本可以判定为**波特率不匹配**或**电气干扰/接线问题**。

---

## 6. 采集数据的完整流程

### 步骤 1 — 确认通信正常

先完成第 5 节的 PING 测试，确保统计正常。

### 步骤 2 — 先不要启动电机

首次连接时建议**先只观察遥测**，确认数据在合理范围内，再考虑下发控制命令。

### 步骤 3 — 开始记录

在 **康复治疗** 页找到 **● 开始记录** 按钮并点击。

按钮变为 **■ 停止记录** 即表示正在记录。

> **注意**：此时数据只缓存在内存中，尚未写盘。

### 步骤 4 — 执行动作 / 康复流程

按需执行：

- 康复页：设置角度、速度、循环次数 → 开始治疗；
- 电机页：手动控制 M1 / M2；
- 协议页：下发参数或批量写入。

### 步骤 5 — 停止记录（关键步骤）

点击 **■ 停止记录**。

**只有在这一步，缓存数据才会真正写入 CSV 文件。**
记录过程中直接关闭程序会丢失全部数据。

### 步骤 6 — 找到 CSV 文件

CSV 写入 **exe 所在目录**，文件名为：

```text
telemetry_YYYYMMDD_HHMMSS.csv
```

例如：

```text
build\Desktop_Qt_6_8_2_MinGW_64_bit_Release\telemetry_20260727_163615.csv
```

### 步骤 7 — 归档到 data 目录

把采集到的 CSV 复制到：

```text
02_采集数据\telemetry\
```

`02_采集数据\telemetry\` 中已有 4 个历史采集文件可供参考。

## 7. CSV 数据内容

CSV 记录的是遥测帧中的 `float_id → 数值` 对，可能包含：

| 类别 | 数据 |
|---|---|
| M1 电机 | 轨迹输入、反馈角度、PID 输出、Kp、Ki、PWM 占空比、最大速度 |
| M2 电机 | 规划位置、实际位置、规划速度、实际速度、力矩、电流限制、最大速度 |
| 力传感器 DR304 | Fx、Fy、Fz、Mx、My、Mz |
| IMU | Roll、Pitch、Yaw |
| 其他 | 传感器角度、传感器电流 |

字段 ID 的完整含义见 `00_项目说明\串口协议说明.md` 第 7 节。

---

## 8. 安全注意事项

1. **首次测试不要直接佩戴到人体上**，先空载验证方向、限位、速度是否正常；
2. 确认急停开关或断电方式随时可用；
3. 第一次运行时把角度和速度范围设置得保守一些；
4. 确认 M1 / M2 零点正确后再运行康复流程；
5. 以下操作会影响设备状态或持久化参数，使用前务必确认：

| 操作 | 风险 |
|---|---|
| M2 机械零点 | 改变零点基准，影响后续所有位置控制 |
| M2 清除故障 | 清除故障标志，可能掩盖真实问题 |
| 力传感器清零 | 改变力/力矩零点基准 |
| `FLASH_SAVE` | 参数写入下位机 Flash，掉电后仍生效 |
| 系统启停 | 启动 TIM2 控制循环，电机可能立即动作 |
| 主动康复 | 力控模式，可能产生非预期运动 |

## 9. 常见问题

### 程序双击后没有窗口

1. 确认用的是 **Release** 构建目录下的 exe；
2. 确认 exe 同目录存在 `Qt6Core.dll`、`Qt6Charts.dll`、`Qt6SerialPort.dll`
   以及 `libgcc_s_seh-1.dll` 等运行库；
3. 若缺失，重新运行 `03_构建与辅助工具\build.ps1` 部署运行库。

### 能打开串口但收不到遥测

见第 5.3 节排查顺序。另外可在 **串口调试** 页用 HEX 接收模式，
直接观察线上是否有原始字节，以区分“没数据”和“协议不匹配”。

### 数据记录为空

- 忘记点“停止记录” → 数据仍在内存中，未落盘；
- 记录期间遥测帧校验失败 → 数据未被解析，检查校验错误计数；
- 记录期间未启动系统/电机 → 下位机可能不上传遥测。

### 错误帧日志越来越大

`error_frames.txt` 位于 exe 同目录，记录所有校验失败的帧。
若它持续快速增长，说明通信质量有问题，应先解决链路问题再采集数据。
